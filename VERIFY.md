# Verify AION Cycle

Document class: public verification.

AION v1 verifies one fixed canonical reference cycle. Verification is local and fail-closed.


## Verification axiom

```text
Trust is ephemeral and lazy-resolved from source.
```

Every artifact, receipt, cache entry, proof file, statement, emission, and intermediate field is treated as untrusted input until the verifier recomputes the lineage needed for the present decision.

A cached artifact may save time, but it may not save trust. If lineage to source cannot be recomputed, verification fails closed.

Reports, emissions, receipts, generated artifacts, and cache entries are snapshots, never authority unless explicitly promoted into durable data/source authority. Code/source files can be durable source artifacts. Trust comes only from fresh recomputation from source.


## PASS and FAIL meaning

| Result | Positive meaning | Negative clamp |
|---|---|---|
| PASS | The fixed canonical cycle closed: route, receipts, artifacts, public inputs, roots, and lineage cohere now. | PASS is not objective truth, privacy, or production security. |
| FAIL | A required relation did not cohere at verification time. | FAIL is not partial success, fallback output, or explanation-as-answer. |

## Quick verify

```bash
make verify
```

Expected output:

```text
PASS
```

If verification cannot recompute the route, receipts, proof artifacts, public inputs, and statement roots, the command prints exactly this on stdout:

```text
FAIL
```

For audit and tests, stderr also carries a controlled public-safe reason code:

```text
FAIL_REASON:<reason_code>
```

The stdout contract remains binary PASS/FAIL. Reason codes are diagnostics, not a third status.

## What verification recomputes

The portable verifier does not trust a stored green flag. It recomputes or checks:

- receipt hashes from receipt bodies,
- phase receipt hashes and ordering,
- cycle receipt child hashes,
- transition emission hashes and final emission chain tip,
- proof artifact hashes from files,
- generation trace receipt hash,
- toolchain receipt hash,
- statement root,
- proof root,
- transcript root binding,
- public digest bits in `public.json`,
- Groth16 positive verification,
- regenerated negative public-input verification in a temporary path.

## What verification refuses to trust

Verification refuses to trust:

- `proof_passed: true` by itself,
- a stored `receipt_hash` without recomputation,
- a stored bad-public file,
- artifact files whose hashes no longer match receipts,
- a statement root that no longer matches its body,
- a proof that verifies only because the verifier was not actually run.

The phase receipt directory is the literal route surface. Each named phase in the route has a receipt. Heavy circuit byproducts are regenerated by `make reproduce` and are not required for lightweight `make verify`. ## Failure matrix

| Change | stdout | stderr reason | Boundary hit |
|---|---|---|---|
| Change `aion.statement.json` `cycle_root` | `FAIL` | `FAIL_REASON:cycle_root_mismatch` | statement root mismatch |
| Change statement `proof_hash` | `FAIL` | `FAIL_REASON:proof_hash_mismatch` | proof/artifact linkage mismatch |
| Change `proofs/v1/public.json` | `FAIL` | `FAIL_REASON:artifact_receipt_recompute_mismatch` | artifact receipt no longer matches files |
| Flip one public digest bit | `FAIL` | `FAIL_REASON:artifact_receipt_recompute_mismatch` | public input hash changed before digest can be trusted |
| Change `proof-artifacts.receipt.json` | `FAIL` | `FAIL_REASON:receipt_hash_mismatch` | receipt body/hash mismatch |
| Change `toolchain.receipt.json` | `FAIL` | `FAIL_REASON:receipt_hash_mismatch` | toolchain receipt body/hash mismatch |
| Change `generation-trace.receipt.json` | `FAIL` | `FAIL_REASON:receipt_hash_mismatch` | generation trace body/hash mismatch |
| Change a phase receipt | `FAIL` | `FAIL_REASON:receipt_hash_mismatch` or `phase_receipt_*_mismatch` | phase route receipt broken |
| Create a stored bad-public file equal to `public.json` | `PASS` for untampered fixture | none | verifier ignores stored bad public and regenerates a bad input in temp space |
| Missing `snarkjs` | `FAIL` | `FAIL_REASON:missing_snarkjs` | real verifier unavailable |
| Missing `circom` during proof generation | `FAIL` | `FAIL_REASON:missing_circom` | real circuit flow unavailable |
| Missing transition emission source root | `FAIL` | `FAIL_REASON:emission_1_source_root_mismatch` | source lineage missing |
| Wrong previous emission hash | `FAIL` | `FAIL_REASON:emission_2_previous_emission_hash_mismatch` | emission chain broken |
| Reordered transition emissions | `FAIL` | `FAIL_REASON:emission_3_transition_index_mismatch` | transition order mismatch |
| Claimed pass on broken emission | `FAIL` | `FAIL_REASON:emission_4_output_identity_mismatch` | self-certification rejected |
| Duplicate field hash during mapback | `FAIL` | `FAIL_REASON:mapback_ambiguous_or_missing_field_hash` | ambiguous mapback fails closed |
| Cache says valid but cached bytes hash mismatches | `FAIL` | `cache_material_hash_mismatch` in direct API | caches store material, never trust |

## Trusted setup distinction

This reference uses Groth16 but does not claim production trusted-setup soundness. The committed proof verifies under the committed verification key; production ceremony governance is out of scope. See `TRUSTED_SETUP.md`.

## Important distinction

`PASS` means the fixed reference route closed. It does not mean universal truth, production provenance, privacy, or hosted security.
